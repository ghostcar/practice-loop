## 1. Цель и роль

Ты — эксперт по Python-разработке (FastAPI, SQLAlchemy 2.0, HTMX, LLM-интеграции, Docker).
Задача — веб-приложение для отслеживания и управления активностями в личных/парных отношениях
(только для взрослых, по обоюдному согласию): каталог задач, сессии, история, геймификация,
штрафы, LLM-подбор задач.

### 1.1. Принципы (обязательны)

1. **Гибридная генерация.** LLM НЕ генерирует откровенный контент. Каталог задач наполняют
   админ и пользователи; пользователь **осознанно отмечает допустимые** задачи (опт-ин);
   LLM выбирает задачу и параметры из допустимого набора на основе истории.
2. **Комплаенс.** Никакого обхода safety-фильтров провайдеров и никакого кодирования/маскирования
   контента для сокрытия от LLM (это нарушает ToS провайдеров и риск блокировки ключа).
   Запрещено даже при указании в требованиях — предложи комплаенс-альтернативу.
3. **Приватность.** Экспорт/удаление данных, обезличенная доска достижений.
4. **Контент** — только личное пространство пользователя, не нарушает законов.
5. **Масштабируемость.** Сейчас один пользователь, но модель данных сразу поддерживает
   межпользовательское взаимодействие (совместные сессии, публичный каталог с авторством).

## 2. Технологический стек

- **Backend:** Python 3.11+, FastAPI (async), Uvicorn, Pydantic v2.
- **DB:** PostgreSQL 15. ORM: SQLAlchemy 2.0 (async) + Alembic.
- **Frontend:** SSR Jinja2 + HTMX + TailwindCSS. Без тяжёлых JS-фреймворков.
- **i18n:** русский и английский, расширяемо. **Темы:** тёмная/светлая с переключателем.
- **LLM:** `openai` SDK (OpenAI-совместимые endpoints). BYOK (bring your own key).
  Стартовые провайдеры:
  - **Omniroute** — локальный шлюз на хосте VPS: `http://host.docker.internal:20128/v1`,
    модель `auto` (умная маршрутизация), **активен по умолчанию**;
  - **Groq** (бесплатный тир, Llama, нативный JSON mode);
  - **OpenRouter** (агрегатор с фолбэком).
- **JSON repair:** `json_repair` + regex-фолбэк.
- **Telegram:** **aiogram 3.x** (вебхук + исходящие уведомления из фоновых задач).
- **Деплой:** Docker Compose (app, PostgreSQL, Nginx + SSL), `.env` для секретов.
- **Бэкапы:** pg_dump по cron, хранение последних N копий.
- **Тесты:** pytest — unit + интеграционные.

## 3. Архитектура

### 3.1. Гибридный пайплайн генерации

```
Каталог Entity (задачи + params_schema)
      │  пользователь отмечает допустимые (опт-ин)
      ▼
Context Builder (история, статистика, активные штрафы, допустимый набор)
      ▼
LLM (конфиг из LLMProviderConfig): выбор задачи + параметры в заданных диапазонах
      ▼
JSON → json_repair → Pydantic-валидация → сохранение в ActivityLog
      ▼
UI: пользователь видит реальную задачу
```

- **LLM-режимы (ADR-029):** два режима работы — `full` (по умолчанию: LLM видит названия,
  генерирует параметры и reasoning) и `abstract` (opaque ID, только позиции — для провайдеров
  со строгими фильтрами). Режим выбирается в настройках `LLMProviderConfig`.
- Промпт: «выбери одну задачу из предоставленного списка, укажи параметры в заданных диапазонах,
  обоснуй выбор на основе истории пользователя».
- **Stateless:** контекст собирается на каждый запрос заново.
- **Tool calling** (опция): `save_activity_log`, `get_user_stats`, `apply_penalty`.

### 3.2. Обработка ошибок LLM

1. `json.loads()` → 2. `json_repair` → 3. regex-извлечение из markdown-блока → 4. после **3 неудач**
   подряд — показать пользователю ошибку и кнопку «Повторить» (без шаблонной подстановки).

### 3.3. Биллинг моделей

Подсчёт токенов/стоимости — отдельно от raw ответа. `raw_llm_response` хранится опционально
(ADR-034): по умолчанию включено, флаг в `LLMProviderConfig`. Usage-метрики (токены, стоимость)
хранятся всегда. Краткий контекст (entity_id, статус) — для точечной отладки.

## 4. Схема БД

### 4.1. Users & Billing
- `User`: id, email, password_hash, `subscription_tier` (поле-заглушка, без логики оплаты),
  locale, theme, created_at.
- `LLMProviderConfig`: id, user_id, provider_name, api_base_url, api_key (шифруется), model_name,
  is_active, usage-статистика (токены/стоимость).

### 4.2. Каталог задач (Entity)
- `Entity`: id, type, real_name, owner_id (NULL = системный), is_public, author_id (для публичных,
  с указанием авторства), params_schema (JSON: допустимые диапазоны параметров), created_at.
- Наполнение: админ (seed 30+ задач) и пользователи (личные задачи; публикация с авторством).
- Опт-ин: пользователь отмечает допустимые для себя задачи.

### 4.3. Сессии и логи
- `ActivitySession`: id, owner_id, участники (many-to-many), status, llm_config_id,
  правила сессии (JSON: штрафы, лимиты), started_at, ended_at.
- `ActivityLog`: id, session_id, user_id, entity_id, status (выполнено / прервано), user_prompt,
  raw_llm_response (полностью), cleaned_response, penalty_applied, penalty_details (JSON),
  usage (tokens/cost), created_at.

### 4.4. Геймификация
- `Achievement` (код, название, условия), `UserAchievement` (user_id, achievement_id, obtained_at,
  контекст получения).
- **Обезличенная доска достижений**: публичная витрина (ник/аноним) с историей — без личных данных.
- XP/уровни/серии — расчётные на основе ActivityLog (или таблица прогресса).

### 4.5. Штрафы (сохранены — ADR-029)
- Настраиваются заранее (в entity.gamification_config или глобально): фикс XP / % / множитель.
- Эскалация штрафов: множитель растёт с пропусками (×1, ×1.5, ×2…).
- PenaltyRedemption: отслеживание отработок (pending→completed→возврат баллов).
- PointsProfile: переиспользуемые шаблоны баллов/штрафов/бонусов.
- Threshold effects: уведомления при пересечении negative/warning/good порогов.
- Безусловные остановки без последствий — не допускаются. Прерывание всегда со штрафом.

### Исторические фазы прототипа (1–4)
Ниже сохранён первоначальный план фаз 1–4 как историческая справка.

### Phase 1 — Фундамент и инфраструктура
- Структура проекта, `pyproject.toml`/`requirements.txt`, ruff.
- Docker: `docker-compose.yml` (db: postgres:15 + volume; app: 8000; nginx: 80/443 → app:8000),
  `Dockerfile` (multi-stage, python:3.11-slim), `nginx.conf`, `.env`.
- `GET /healthz`.
- Модель User, JWT-аутентификация, Alembic-миграции, простая регистрация.
- i18n EN/RU + переключатель темы (dark/light) с сохранением выбора.
- **Приёмка:** `docker compose up` поднимает БД и `/healthz`; регистрация/логин работают;
  тема и язык переключаются.

### Phase 2 — Каталог и конфиги
- CRUD `Entity`: seed 30+ задач, личные, публикация с авторством, опт-ин допустимости.
- CRUD `LLMProviderConfig`: seed-пресеты **Omniroute** (активный, `auto`), Groq, OpenRouter.
- Базовая админ-панель (управление каталогом, пользователями) — расширяемая.
- **Приёмка:** CRUD работает в UI; пресеты создаются; админ управляет каталогом.

### Phase 3 — LLM-пайплайн
- Context Builder; OpenAI-клиент из `LLMProviderConfig`; JSON repair (3 попытки → ошибка + повтор);
  tool calling (`save_activity_log`, `get_user_stats`, `apply_penalty`);
  `POST /tasks/generate`; подсчёт токенов/стоимости; контент по locale пользователя.
- **Приёмка:** задача сохраняется в ActivityLog; сломанный JSON чинится; 3 неудачи → ошибка
  + кнопка «Повторить».

### Phase 4 — UI, сессии, геймификация, уведомления
- HTMX: дашборд, история, статистика, доска достижений (обезличенная).
- Сессии: создание, участники, правила, статусы, совместные задачи.
- Выполнение/прерывание задачи со штрафом.
- Геймификация: XP, уровни, серии, достижения, бейджи + кастомные правила (формулы XP; правила
  сессий; множитель серий; эскалация штрафов; недельные челленджи; комбо в сессии; случайные
  бонус-задачи; совместные достижения).
- Уведомления: in-app + Telegram (aiogram 3.x).
- Приватность: экспорт данных; удаление аккаунта (полное) или с сохранением обезличенных данных.
- **Приёмка:** полный цикл «каталог → сессия → задача → выполнение/прерывание → XP → достижения»;
  уведомления приходят в Telegram.

## 8. Чек-лист настройки VPS (Docker)

**1. Установка Docker** (Ubuntu/Debian):
```bash
docker -v                                  # проверить
sudo apt update
sudo apt install docker.io docker-compose-v2 -y
sudo systemctl enable --now docker
sudo usermod -aG docker $USER              # перелогиниться, чтобы права применились
```

**2. Запуск приложения:**
1. Скопировать проект на сервер.
2. Заполнить `.env` (пароли БД, JWT-ключ, Telegram-токен, ключи провайдеров).
3. `docker compose up -d --build` → проверить `/healthz`.
4. Nginx + SSL (Let's Encrypt): домен → app:8000, редирект 80 → 443.
5. Бэкапы: pg_dump по cron, хранение последних N копий, проверить восстановление.
6. **Omniroute** крутится на хосте вне compose (уже настроен): контейнер app обращается к нему
   через `http://host.docker.internal:20128/v1` (URL переопределяется в `.env`).
