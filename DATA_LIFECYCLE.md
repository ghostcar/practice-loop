# Practice Loop — жизненный цикл данных (DATA_LIFECYCLE.md)

> Статус: нормативный документ по данным. Закрывает PQ-006.
> Актуально на: 16 августа 2026 года.
> Принятые решения: `PRODUCT_DECISIONS.md` (PD-012, PD-013, PD-016).
> Этот документ обязателен к применению до Media Vault, Health и Social-расширений.

## 1. Назначение

Определяет классификацию данных, политики хранения, экспорта, удаления, производных копий и
общих артефактов. Цель — чтобы каждый модуль и каждая операция (включая удаление аккаунта и
публикацию проекции) имели однозначный ответ: **где данные, кто их видит, сколько живут, что
происходит при удалении и отзыве**.

Документ описывает целевой контракт; фактическая реализация проверяется по коду. Частичное
совпадение с текущим состоянием помечено.

## 2. Классификация (PD-012)

| Слой | Определение | Примеры | Видимость |
|---|---|---|---|
| **Private Record** | исходная личная запись владельца | задача, сессия, журнал, лекарство, состояние, замер, приватное медиа | только владелец |
| **Shared Dynamic Record** | договорённость/задание/событие конкретной Dynamics | соглашение, задание, check-in, отчёт в Dynamics | владелец + участник Dynamics |
| **Shared Artifact** | намеренно переданный отчёт или медиафайл | переданное фото, выгруженный список для врача | получатель, до отзыва |
| **Published Projection** | неизменяемый redacted snapshot | публикация статуса Timer, пост Social | по выбранной видимости |

Ключевое правило: **проекция ≠ оригинал**. Публикация не превращает Private Record в общий
объект и не открывает будущие изменения Personal.

## 3. Классификация по доменам

| Домен | Слой по умолчанию | Особые правила |
|---|---|---|
| Activity Tracker (задачи/сессии/история) | Private Record | публикация только через проекцию |
| Chastity Timer (сессии/окна/штрафы) | Private Record | Social-статус — только проекция |
| Sexual Journal | Private Record | отдельное удаление; связь по ID, без раскрытия |
| Personal Care | Private Record | фото динамики — Private |
| Medication / Health / Cycle | Private Record | **не участвует в игре**; экспорт врачу — Shared Artifact по явному действию |
| Training / Diet / Measurements | Private Record | — |
| Media | Private Record (original) | derivatives отдельно; передача — только Shared Artifact |
| Social (профиль/отношения/посты) | Published Projection + Shared Dynamic Record | исходник остаётся Private |
| D/s (гранты/соглашения) | Shared Dynamic Record | аудит грантов, отзыв мгновенный |
| Push/API-токены | Private (служебное) | SHA-256 refresh в БД, revoke |

## 4. Retention (сроки хранения)

| Категория | Политика | Примечание |
|---|---|---|
| Активные Personal-записи | хранятся, пока аккаунт активен | без автоматического удаления без решения владельца |
| `raw_llm_response` | опционально; TTL по флагу конфига | usage-метрики (токены/стоимость) — всегда |
| Медиа original | хранится до явного удаления/удаления аккаунта | derivatives регенерируются из original |
| Verification challenge (HMAC) | кратковременный, с `expires_at` | plaintext кода не хранится (только HMAC) |
| Отозванные Shared Artifact | доступ прекращается немедленно | копия у получателя не гарантированно удаляется |
| Обезличенные данные (achievement board) | могут пережить удаление аккаунта | только если владелец выбрал сохранение обезличенного |
| Бэкапы (pg_dump) | последние N копий по cron | восстановление проверяется отдельно |

## 5. Экспорт и restore

- Полный экспорт (`CURRENT_STATE.md`/`FUNCTIONAL.md`: CSV/JSON, full export, CLI) должен
  покрывать **все** Private Record нового модуля; новые модули обязаны добавить свой сегмент
  в экспорт в том же vertical slice.
- Экспорт для врача (Medication) — отдельный, ограниченный `Shared Artifact` (список + история),
  создаётся только явным действием пользователя.
- Restore/roundtrip проверяется тестом (migration roundtrip + экспорт→импорт).

## 6. Удаление

| Операция | Поведение |
|---|---|
| Удаление аккаунта (полное) | каскадное удаление всех Private/Shared Dynamic Record и originals; проекции — по выбору владельца |
| Удаление с сохранением обезличенного | достижения/статистика остаются без PII, только при явном согласии |
| Удаление модуля (напр. Sexual Journal) | удаляются только его записи; связи с другими модулями по ID обнуляются/проекции помечаются |
| Отзыв Shared Artifact | доступ прекращается; история доступа фиксируется |
| Удаление проекции | проекция исчезает; original не затрагивается |

Продукт **не обещает** удалить уже скачанные внешние копии или скриншоты (PD-012).

## 7. Производные и копии

- **Derivatives** (thumbnail, оптимизированные версии) хранятся отдельно от original и
  регенерируются из original; при удалении original удаляются и derivatives.
- **Shared copies** создаются только как `Shared Artifact` (намеренное действие) и получают
  собственный `access_grant` (получатель, срок, revoke, история).
- **LLM**: чувствительное медиа не отправляется облачному AI без отдельного согласия; vision-
  верификация работает через конфигурируемого провайдера и не сохраняет plaintext кода.

## 8. Health-специфика (PD-013)

- Medication/Health/Cycle — строго Private Record; **никогда** не попадают в штрафы, публичные
  рейтинги или игровые события.
- Передача во внешний контур (врачу) — только явный `Shared Artifact` (экспорт списка/истории).
- Расчётная фаза Cycle не выдаётся за достоверный факт.

## 9. Consent

- Согласие выдаётся один раз на конкретную цель и версию условий и действует всё время
  пользования порталом. Повторный запрос допустим только после явного отзыва, существенного
  изменения условий (новая `terms_version`) либо для впервые включаемого в профиле модуля.
- При первом входе запрашиваются согласия для уже включённых модулей; каждый новый модуль
  запрашивает собственное согласие в момент его включения. Отключение модуля не является отзывом.
- История `granted/revoked` append-only: отдельные записи не удаляются; они исчезают только
  вместе с аккаунтом в общем privacy workflow.
- Vision-LLM и expanded LLM требуют отдельного актуального согласия. Для BYOK явно фиксируется,
  что провайдера, endpoint и ключ принёс и настроил пользователь, данные уходят по условиям этого
  провайдера, а пользователь отвечает за его выбор и настройку. Это не снимает с Practice Loop
  ответственность за безопасность и обработку данных внутри портала.
- Discretion mode нейтрализует тексты уведомлений, но не меняет хранение/аудит данных.

## 10. Правила для агента

1. Новый модуль не вводит таблицу без явной классификации слоя (Private/Shared/Artifact/Projection).
2. Любая передача данных за пределы Personal идёт через Shared Artifact или Published Projection.
3. Health-данные запрещено подключать к penalty engine (PD-013) — это проверяется тестом границы.
4. Экспорт/удаление нового модуля добавляется в том же vertical slice, что и сам модуль.
5. Retention/cleanup-политики для нового модуля фиксируются здесь до его поставки.
