# EQ-0014 — LockTimer penalty wiring в HTTP

## Вопрос

Как привязать `apply_penalty` к HTTP-путям? Решение принято: штраф применяется доменным сервисом
при `skip_task` и позднем `close_slot`, а HTTP возвращает фактический результат.

## Контекст

`apply_penalty` (ADD_TIME / BLOCK_NEXT_SLOT / MARK_TASK_FAILED / POINTS, идемпотентность, cap по
`max_end_at`) вызывается через политики правил. `POST .../skip` и `.../close` возвращают сериализованный
результат penalty, а UI показывает фактическое применение или отсутствие штрафа.

## Решение

Принято по ADR-072: `skip_task` использует `rule.penalty_policy`, позднее закрытие слота —
`rule.late_close_policy`; политика задаётся явно в правиле, поэтому не вводится скрытый штраф
по умолчанию. Идемпотентность обеспечивается ключами `skip:{occurrence_id}` и
`late_close:{occurrence_id}`. Отдельный endpoint для ручного применения штрафа не нужен.
