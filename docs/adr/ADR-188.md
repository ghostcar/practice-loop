# ADR-188 — `alembic check`: полное покрытие моделей и фиксация остаточного schema drift

- **Дата**: 2026-09-04
- **Статус**: принято
- **Связано**: TECH_DEBT S6, S4; ADR-187 (094); миграции 068, 069

## Контекст

`alembic check` (autogenerate-сравнение models ↔ живая БД) использовался как кандидат
в pre-deploy gate (CURRENT_STATE.md), но был непригоден:

1. `alembic/env.py` импортировал **подмножество** моделей (не были подключены `attachment`,
   `calendar`, `diet`, `points`, `training_log`, `ds_suite.CapabilityGrantClaimAttempt` и др.).
   Autogenerate видел неполный metadata и предлагал **удалить** существующие таблицы
   (`remove_table` для `attachments`, `diets`, `points_transactions`, `training_log_entries`,
   `calendar_*`, `penalty_redemptions` и т.д.) — ложноположительный результат.
2. Помимо этого, сравнение вскрыло **реальные расхождения ORM ↔ миграции**:
   - `LockSlotRule` (модель) не объявлял 4 колонки, добавленные миграцией 068
     (`chastity_device_id`, `keyholder_type`, `auto_pause_on_health_drop`, `extension_history`);
   - `TrainingLogEntry` не объявлял `equipment_item_ids` (миграция 069).

## Решение

1. **`alembic/env.py` дополнен до полного покрытия моделей** — autogenerate теперь видит
   все таблицы, `remove_table`-ложные срабатывания устранены.
2. **Исправлены модели** в сторону БД (БД — источник истины, колонки созданы миграциями):
   - `LockSlotRule`: добавлены 4 колонки по схеме миграции 068 (`extension_history` —
     `JSON().with_variant(JSONB, "postgresql")` для совместимости с SQLite-тестами);
   - `TrainingLogEntry`: добавлен `equipment_item_ids` (JSON, в стиле `TrainingDay`).
3. **Остаточный drift НЕ реконсилится в этой сессии** — он зафиксирован как долг S6
   (отдельная reconciliation-миграция по решению владельца):

| Категория | Кол-во | Пример |
|---|---|---|
| Переименование индексов | 84 remove / 88 add | `ix_abpr_activity_id` → `ix_activity_body_part_requirements_activity_id` |
| Тип колонок JSONB ↔ JSON | 76 modify | модели: JSONB; миграции создали: JSON (и наоборот) |
| FK ondelete | 8 remove / 10 add | модели: `ondelete="CASCADE"`; БД: без ondelete |
| Unique-констрейнты | 8 remove / 2 add | разница имён/состава |

Drift не влияет на runtime (ORM работает с фактическими типами), но `alembic check`
останется красным до reconciliation-миграции; как pre-deploy gate его включать нельзя.

## Последствия

- `alembic check` снова осмыслен: любые будущие правки моделей/миграций будут видны
  поверх известного baseline (S6).
- Модели locktimer/training приведены в соответствие с БД — устранено «тихое»
  расхождение (колонки существовали в БД, но не маппились ORM).
- Новые модели должны добавляться в `alembic/env.py` (или в `app/models/__init__.py`)
  при создании.
