# ADR-190 — Medication: «активный элемент», состав (компоненты) и суточные пределы

- **Дата**: 2026-09-04
- **Статус**: принято (проектирование; реализация фазами E–G, см. K-MEDICATION-SUBSTANCES-SPEC)
- **Связано**: ADR-189 (аптечки/режимы/курсы), ADR-084 (Medication Organizer), PD-013 (relief-only)
- **Инициатива владельца**: поле «МНН / Действующее вещество» смешивает сущности; нужен
  «активный элемент» как каноническая сущность для группировки/поиска/замены; препарат может
  содержать **несколько действующих веществ** (Фемостон 2/10, витаминно-минеральные комплексы)
  и разные дозировки для разных таблеток внутри одной пачки; нужны **суточные пределы** веществ
  для сверки и **явное разрешение превышения**; автопоиск по наименованию должен заполнять
  форму целиком, включая состав.

## Контекст (факты на 2026-09-04)

1. `medications.active_ingredient` — свободный текст (одно поле «МНН / Действующее вещество»);
   группировки/поиска/замены по нему нет.
2. Модель однокомпонентная: один препарат = одно действующее вещество. Примеры владельца
   (Фемостон 2/10: эстрадиол 2 мг и дидрогестерон 10 мг в разных таблетках пачки; витаминные
   комплексы с десятком компонентов) не представимы.
3. Нет суточных пределов веществ и механизма сверки/разрешения превышения.
4. Автопоиск по наименованию (`/medications/autofill-info` → `pharma_enricher`) покрывает
   только ~13 seed-записей; ветка «LLM» — мок-заглушка без реального вызова, возвращает
   «Дженерик …», а не состав; multi-составные наименования не заполняются.
5. `LOCAL_PHARMA_SEED` — справочник «торговое имя → действующее вещество»: источник seed-слоя.

## Решения (по выбору владельца + уточнениям)

1. **Сущность `med_substances`** — канонический «активный элемент»: `name`, `norm_key` (unique),
   `inn` (МНН хранится на сущности), `synonyms` (JSON, поиск), `daily_max_amt/daily_max_unit/
   daily_max_note` — **суточный предел** (справочно, для сверки), `is_custom`, timestamps.
   Отдельного поля МНН на препарате нет.
2. **Состав — many-to-many**: `med_components` (medication_id, substance_id, amount, unit,
   variant_id nullable, sort_order). Препарат = 1..N компонентов. `med_variants` — «таблетки
   внутри одной пачки» (Фемостон 2/10: variant «белые 1–14» — эстрадиол 2 мг; «серые 15–28» —
   эстрадиол 2 мг + дидрогестерон 10 мг; count_per_pack).
3. **Суточные пределы и разрешение превышения**: предел на веществе; сверка — сумма
   планируемого на день приёма по компонентам vs `daily_max` (одинаковые единицы); явное
   разрешение превышения — флаг `medications.allow_ul_override` + при сверке предупреждение
   с кнопкой «принять с превышением» (отметка в приёме). Реализация сверки — фаза G; модель
   и флаг — уже в E.
4. **Правила замены** (автовыбор при совпадении состава + формы): автовыбор, когда у кандидата
   тот же набор компонентов (norm_keys) и та же лекарственная форма; дозы пересчитываются по
   компонентам (мг). Неполное совпадение/поливитамины — только предложение. Фаза F.
5. **Автопоиск по наименованию (фаза E)**: seed (расширен, включая multi-компонентные записи и
   разбор «Фемостон N/M» по маске) → реальный LLM-разбор через `call_llm` (json_mode) при
   активном BYOK-конфиге → детерминированный fallback. Ответ: поля формы + `components[]`
   (name/inn/amount/unit/variant). Результат — предзаполнение формы, сохраняется пользователем
   (human-in-the-loop). При неудаче — понятное «не найдено», а не мусорное автозаполнение.

## Границы

- Личное пространство пользователя, relief-only (PD-013); автоподстановки видны и подтверждаются.
- `LOCAL_PHARMA_SEED` → системный seed `med_substances` (is_custom=false), пользовательские
  строки создаются find-or-create по norm_key.
- Соль/эфир — отдельная строка (эстрадиола валерат ≠ эстрадиол); синонимы через `synonyms`.

## Фазы

- **E — Сущность, состав, автопоиск, группировка**: миграция 097 (`med_substances` +
  `med_variants` + `med_components` + `medications.allow_ul_override`), backfill legacy
  `active_ingredient` → одно вещество/компонент; сервис normalize/find-or-create и синхронизация
  компонентов; `pharma_enricher`: компоненты в seed + маска Фемостон + реальный LLM-разбор;
  форма: список компонентов (вещество+доза+единица+вариант), автозаполнение заполняет состав;
  карточка и группировка «по действующему веществу» + поиск (имя/вещество/МНН/синонимы);
  i18n; тесты.
- **F — Замена**: состав+форма → автовыбор с пересчётом мг; «Эквиваленты» при открытии;
  `med_intakes.substituted_for_id`; JSON parity.
- **G — Суточные пределы и схемы пачек**: сверка дня (сумма компонентов vs daily_max,
  предупреждение, «принять с превышением»), учёт вариантов пачки в расписании дня,
  напоминания/TG; эквивалентное покрытие в `course_summary`.

Каждая фаза: ruff, таргетные pytest, single alembic head, i18n parity, деплой по команде.
Спека: `docs/wiki/K-MEDICATION-SUBSTANCES-SPEC.md`.
