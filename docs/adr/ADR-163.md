# ADR-163 — Service Layer Extraction — health.py → health_service.py

**Decision:** Extract all business logic from `app/api/health.py` (970 lines) into `app/services/health_service.py` (770 lines), leaving `health.py` as thin HTTP wrappers (385 lines).

**What moved to service:**
- Cycle helpers: `cycle_phase`, `day_of_cycle` (reused by care_service, journal, insights)
- Serializers: `state_dict`, `lab_dict`
- HealthState CRUD: `save_health_state`
- LabRecord CRUD: `add_lab`, `delete_lab`
- CycleSettings CRUD: `save_cycle_settings`
- CycleEvent CRUD: `add_cycle_event`, `delete_cycle_event`
- Cycle context: `get_cycle_context`
- Dashboard: `health_summary`
- LLM analysis: `analyze_labs_async`
- Body cycle: `get_body_cycle_page_context`, `log_body_cycle`
- JSON API: `json_health_summary`, `json_list_states`, `json_list_labs`, `json_cycle`, `json_save_state`, `json_add_lab`, `json_add_cycle_event`, `json_save_cycle_settings`
- Pydantic bodies: `StateBody`, `LabBody`, `CycleEventBody`, `CycleSettingsBody`
- Parsers: `parse_analysis_param`, `parse_scale`

**Cross-module imports (10 files):** Re-exported from `health.py`:
- `_cycle_phase` → care_service, journal, insights
- `_day_of_cycle` → care_service, journal
- `_get_cycle_context` → telegram bot
- `_health_summary` → today, dashboard

**Status:** accepted (implemented, 1380 tests green, deployed).
