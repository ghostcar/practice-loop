# ADR-204 — Штрафные задания пояса из справочника активностей (Entity), селектор нарушений, эскалация, синглтон-черновик и цифровой код верификации

**Date:** 2026-09-09
**Decision:** В рамках углубления дисциплинарного контура и повышения удобства использования утверждены следующие решения:
1. **Цифровой код верификации:**
   - Генератор одноразовых проверочных кодов (`generate_verification_code`) переведен на криптографически стойкие 6 цифр (`0-9`) без букв. Это устраняет неоднозначность и ошибки при записи от руки на бумаге и оптическом контроле пломбы.
2. **Исключение черновиков из истории:**
   - В блоке «История ношения» (`recent sessions`) черновики (`state == 'draft'`) отфильтрованы и не показываются; отображаются исключительно реальные сессии (`active`, `completed`, `safety_stopped`).
3. **Синглтон-черновик сессии:**
   - У пользователя может существовать только один черновик сессии одновременно. При попытке создания нового черновика через интерфейс («+ Новая сессия») или API (`POST /locktimer/new`) система автоматически открывает существующий сохраненный черновик без пложения мусорных записей.
4. **Штрафные задания из справочника активностей (Entity):**
   - В политику дисциплины (`discipline_policy["penalty_tasks_config"]`) внедрен выбор конкретных активностей из каталога `Entity`:
     - Привязка к типам нарушений: `any` (любое), `late_return` (опоздание возврата в пояс), `breach_relapse` (самовольное снятие / срыв), `task_missed` (пропуск обязательного задания), `verification_missed` (пропуск фотоконтроля).
     - Режим назначения: `random_one` (случайная одна из подходящих) или `all` (назначать все подходящие активности одновременно).
     - Динамическая эскалация параметров нагрузки: для динамических активностей начальное значение (`initial_value`, напр. 30 приседаний, 60 сек планки) прогрессивно умножается на коэффициент эскалации (`initial_value * escalation_multiplier^(streak-1)`).
     - Назначение штрафа создает реальные задачи `ActivityLog` в Плане дня пользователя со статусом `planned`, категорией `discipline`, дедлайном и привязкой к сессии.
5. **Совместимость с рефакторингом модульности:**
   - Все компоненты дисциплинарных штрафов изолированы в модуле `app/locktimer/` и стандартных интерфейсах `Entity` / `ActivityLog`, исключая конфликты с параллельным рефакторингом других подсистем.
**Status:** ✅ принято к реализации.
