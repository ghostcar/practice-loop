# ADR-162 — Service Layer Extraction — medication.py → med_service.py

**Decision:** Extract all business logic from `app/api/medication.py` (1303 lines) into `app/services/med_service.py` (1069 lines), leaving `medication.py` as thin HTTP wrappers (536 lines).

**What moved to service:**
- Serializers: `med_dict`, `stock_dict`, `schedule_dict`
- Schedule logic: `doses_today`, `schedule_summary`
- Validators: `get_med`, `get_kit`, `get_schedule`, `get_stock`
- CRUD: `create/update/delete_medication`, `create/delete_stock`, `create/delete_schedule`, `create/delete_kit`
- Intake: `record_intake` (shared for form + JSON)
- LLM: `find_analogs`, `autofill_info`
- Export: `get_csv_export`, `get_json_export`
- Migration: `migrate_inventory` (inventory → medication)
- JSON lists: `json_list_medications`, `json_list_stocks`, `json_list_schedules`, `json_list_kits`
- Pydantic bodies: `MedicationBody`, `StockBody`, `ScheduleBody`, `KitBody`, `IntakeBody`

**Cross-module imports:** `_schedule_summary` re-exported from `medication.py` → `med_service.schedule_summary`

**Status:** accepted (implemented, 1380 tests green, deployed).
