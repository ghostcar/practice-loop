# ADR-202 — Удаление черновиков сессий пояса верности

**Date:** 2026-09-09
**Decision:** В рамках оптимизации управления сессиями таймера пояса верности и очистки невостребованных предварительных конфигураций утверждена возможность удаления черновиков:
1. **Безопасность и строгое ограничение по статусу:**
   - Удалению подлежат исключительно сессии в статусе `draft` (`session.state == 'draft'`).
   - Попытка удаления сессии в статусе `active`, `paused`, `safety_stopped` или `completed` отклоняется с ошибкой `400/409` (`ValueError`). Активные и завершенные сессии сохраняются в дисциплинарном аудите и неизменяемой истории ношения (ADR-029, ADR-197).
2. **Очистка связанных сущностей:**
   - При удалении сессии каскадно очищаются предварительные правила снятия (`LockSlotRule`), правила обязательных задач (`LockTaskRule`), снимки конфигурации (`LockSessionSnapshot`).
   - Социальный субъект `SocialSubject` (`subject_type='timer.session'`) дерегистрируется/удаляется из реестра.
   - Если к сессии было привязано физическое устройство из инвентаря (`device_id`), привязка снимается, устройство гарантированно возвращается в статус `available` (если не занято другим процессом).
   - Фиксируется запись в аудит-логе: `event_type="locktimer.session.draft_deleted"`.
3. **API и веб-интерфейс:**
   - Эндпоинт: `POST /api/v2/locktimer/sessions/{id}/delete` с поддержкой flash-редиректа на `/locktimer` для веб-форм и `json_body={"status": "deleted"}` для API-клиентов.
   - Дашборд `/locktimer`: в блоке «Черновики сессий» для каждого элемента добавлена кнопка удаления с иконкой корзины `{{ icon('delete', 'w-4 h-4') }}` и модальным подтверждением действия `data-confirm`.
   - Страница черновика `/locktimer/sessions/{id}`: в блоке действий (`session.state == 'draft'`) добавлена явная кнопка «Удалить черновик» с подтверждением.
**Status:** ✅ принято к реализации.
